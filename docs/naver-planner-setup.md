# 네이버 블로그 작성 도우미 — 설정 안내

관리자 화면: `/admin/naver-planner` (관리자 메인의 **BLOG PLANNER** 버튼)

흐름: 지점 선택 → 검색광고 API로 연관 키워드·월간 검색량 조회 → 추천 키워드(이유 포함) → 블로그 검색 API로 제목·요약·링크 확인 → 제목 3개·본문·사진 위치·상담 안내 초안 작성 → 검토 후 복사

자동 발행 기능은 없습니다.

---

## 1. 네이버 검색광고 API 발급 (검색량 조회용)

1. https://searchad.naver.com 에 접속해 네이버 아이디로 로그인합니다.
   - 광고주 계정이 없으면 **신규 가입**에서 광고주 가입을 먼저 합니다. 사업자 계정이 아니어도 개인 광고주로 가입할 수 있습니다.
2. 로그인 후 **광고시스템**으로 들어갑니다.
3. 상단 메뉴 **도구 → API 사용 관리**를 누릅니다.
4. **네이버 검색광고 API 서비스 신청**을 누르면 아래 3가지가 나옵니다.
   - **CUSTOMER_ID** (숫자) → `NAVER_SEARCHAD_CUSTOMER_ID`
   - **액세스라이선스** → `NAVER_SEARCHAD_API_KEY`
   - **비밀키** (보기 버튼으로 확인) → `NAVER_SEARCHAD_SECRET_KEY`
5. 키워드 도구 조회만 쓰므로 광고를 집행하거나 광고비를 충전하지 않아도 됩니다. 단, 네이버 정책은 바뀔 수 있으니 조회가 막히면 광고시스템 공지를 확인하세요.

> 비밀키는 다른 사람에게 보여주거나 메신저·깃허브에 올리지 마세요. 노출됐다면 같은 화면에서 삭제 후 다시 발급합니다.

## 2. 네이버 검색 API 발급 (블로그 검색 결과 조회용)

1. https://developers.naver.com 에 접속해 로그인합니다.
2. 상단 **Application → 애플리케이션 등록**을 누릅니다.
3. 입력 항목
   - 애플리케이션 이름: `스트롱복싱 블로그 도우미` (자유)
   - 사용 API: **검색** 선택
   - 비로그인 오픈 API 서비스 환경: **WEB 설정** 추가 → 웹 서비스 URL에 `https://strongboxing.kr` 입력 (로컬에서도 쓸 거면 `http://localhost:3000` 도 추가)
4. **등록하기**를 누르면 **Client ID**, **Client Secret**이 나옵니다.
   - Client ID → `NAVER_SEARCH_CLIENT_ID`
   - Client Secret → `NAVER_SEARCH_CLIENT_SECRET`
5. 검색 API는 하루 호출 한도가 있습니다(내 애플리케이션 → API 설정에서 확인). 이 도구는 버튼을 누를 때만 1회 호출합니다.

## 3. 환경변수 설정

키는 **`.env.local` 파일에만** 넣습니다. 이 파일은 `.gitignore`에 들어 있어 저장소에 올라가지 않습니다.
화면(브라우저)에는 “설정됨 / 환경변수 없음”만 표시되고 키 값은 보내지 않습니다.

1. 서버(사이트가 실행되는 컴퓨터)의 프로젝트 폴더에서 `.env.local`을 엽니다. 이미 `DB_HOST`, `OPENAI_API_KEY` 등이 들어 있는 그 파일입니다.
2. 맨 아래에 다음 줄을 추가하고 `=` 뒤에 발급받은 값을 붙여 넣습니다. 따옴표와 앞뒤 공백 없이 넣습니다.

```
NAVER_SEARCHAD_API_KEY=
NAVER_SEARCHAD_SECRET_KEY=
NAVER_SEARCHAD_CUSTOMER_ID=
NAVER_SEARCH_CLIENT_ID=
NAVER_SEARCH_CLIENT_SECRET=
```

3. 선택: 초안 작성 모델을 바꾸고 싶으면 `NAVER_PLANNER_TEXT_MODEL=gpt-5-mini` 처럼 추가합니다. 없으면 `BLOG_AUTO_TEXT_MODEL` 또는 `gpt-5-mini`를 씁니다. OpenAI 키는 기존 `OPENAI_API_KEY`를 그대로 씁니다.
4. **절대 `NEXT_PUBLIC_`을 앞에 붙이지 마세요.** 붙이면 브라우저로 키가 노출됩니다.
5. 저장 후 빌드·재시작합니다.

```
npm run build && pm2 restart all
```

6. `/admin/naver-planner` 상단에 세 개 모두 **설정됨**이 초록색으로 나오면 완료입니다.

## 4. DB 테이블

처음 화면을 열 때 자동으로 만들어집니다 (`nbp_branches`, `nbp_keyword_lookups`, `nbp_drafts`). 직접 만들고 싶다면:

```
mysql -u root -p strongboxing < database/naver_planner_schema.sql
```

## 5. 처음 쓸 때 할 일

1. 지점마다 **지점 정보 수정**을 눌러 주소·운영시간·전화·예약 링크를 확인하고 **확인됨**에 체크합니다.
   - 처음 값은 홈페이지 지점 페이지 표기값이며 “확인 필요” 상태입니다.
   - 가격은 비어 있습니다(입력 필요). 확인된 금액만 넣으세요.
   - 확인되지 않은 항목은 초안에 `[입력 필요: 가격]`, `[확인 필요] ○○` 처럼 표시되고 본문에는 구체 값이 들어가지 않습니다.
2. **지점 특징**에 직접 확인한 사실(가까운 역, 주차, 장비 등)을 적습니다. 비어 있으면 시설 묘사 없이 작성됩니다.
3. **주제 방향**을 지점마다 다르게 적습니다. 지점별 글이 지역명만 바뀌지 않게 하는 기준이 됩니다.

## 동작 원칙

- 검색량은 API가 준 값 그대로 표시합니다 (`< 10` 포함). 조회 일시가 함께 저장되고, 조회에 실패한 값은 만들지 않습니다.
- 검색량 하한이 없습니다. 지역어 + 복싱 + 목적(체험·가격·초보 등)이 뚜렷하면 검색량이 적어도 추천합니다.
- 블로그 검색은 API의 **제목·요약·링크만** 사용하며 본문은 가져오지 않습니다. 초안의 참고 메모도 “검색 결과 제목·요약 기준”으로 작성됩니다.
- 초안 생성 후 자동 검사: 검색 결과와 같은 문장 구간, 회원 후기·성과 표현, 확인 안 된 가격, 단체 수업 시간표 표현, 다른 지점 초안과의 유사도.
